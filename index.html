Unit tests gate the pipeline
Unit tests check one function in isolation. Integration tests check components together, smoke tests check a deployment is alive, end-to-end tests walk a user journey. Developers run python -m pytest tests/ locally; CI re-runs it as a required check.


app/calculator.py
def add(a, b):
    return a + b

tests/test_calculator.py
from app.calculator import add
def test_add():
    assert add(2, 3) == 5
$ python -m pytest tests/



GitOps: Git holds the desired state


GitHub Actions builds and tests, pushes the image to ECR, then commits a new digest to a separate GitOps repo. Argo CD watches that repo and applies Kubernetes manifests (plain YAML, Kustomize or Helm) to EKS. Actions does CI; Argo CD does deployment.
Synced: cluster matches Git. OutOfSync: Git changed or the cluster drifted. Healthy: resources are running and ready. Rollback = revert the Git commit (or kubectl rollout undo for emergencies, then fix Git).

What a Forward Deployed Engineer does
An FDE works with customers to turn a product into a working solution in the customer's own environment, then feeds what was learned back to the product team. Exact scope varies by company.
The job
Scope the problem, build integrations and prototypes, deploy into the customer's systems, and make sure it delivers the agreed outcome.
FDE vs software engineer
A software engineer builds the general product for many customers. An FDE solves one customer's problem and generalizes what is reusable.
FDE vs solutions architect
An architect designs and advises. An FDE also writes and ships production code.
FDE vs support
Support resolves tickets. An FDE delivers outcomes and new capabilities.
Where you work
Customer sites and clouds, regulated or air-gapped networks, and legacy systems.
Traits that matter
Customer empathy, fast prototyping, plain communication with non-technical people, ownership and comfort with ambiguity.

The FDE technical toolkit
Breadth matters: you integrate, deploy and debug across the customer's stack. For deployment depth, see the DevOps track.
APIs and integrations
REST, GraphQL, webhooks, pagination, retries with idempotency, rate limits, contract tests.
Data
SQL, ETL and ELT, schema mapping, data quality checks, CSV and Parquet, handling bad rows.
Code
Python or TypeScript for connectors, scripts and small services, with tests and logging.
Auth and security
OAuth2, OIDC and SAML SSO, RBAC, secrets, audit logs, PII handling, data residency.
Gen AI
Prompting, structured outputs, retrieval (RAG), evaluation sets, guardrails, cost and latency. Required level: Strong.
Agentic AI
Tool calling, MCP, agent loops, permissions, human approval, traces and agent evaluation. Required level: Working to Strong.
Deployment
Docker, Kubernetes, Terraform, CI/CD, private networking, on-prem and air-gapped installs, observability.

Security & production practice
  • Protect main and develop: required PR reviews and required status checks.
  • Use GitHub Environments with required reviewers for production; approval is a configured control, not a property of main.
  • Authenticate to AWS with GitHub OIDC and least-privilege IAM roles. No long-lived access keys; no secrets in repo files.
  • Scan images, use immutable digests, and build once, promote many. Cross-account ECR access needs repository policies on both sides.
  • Use Kubernetes RBAC, private EKS networking, CloudWatch monitoring and a tested rollback path.
  • A green CI run never guarantees production deployment.
